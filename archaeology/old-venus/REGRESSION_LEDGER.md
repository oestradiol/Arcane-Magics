# Historical regression ledger

The successor implementation should make these Old Venus failure classes difficult to reproduce silently:

- evidence connectivity passing because the claim inserted itself into the graph;
- “live” evidence declared by hard-coded arrays;
- unknown or unverifiable state counted as verified;
- detector output narrated as if execution occurred;
- authorization performed after an irreversible action;
- model/world mismatch “corrected” by rewriting the world toward the model;
- ambiguous causal return dropped instead of becoming a residual;
- source multiplicity counted as independent correction;
- representation or hash integrity treated as semantic validity;
- a proof object treated as a discharged proof;
- identity or metadata-only perturbations counted as adversarial transformations;
- connected-component definitions making external leakage vanish by construction;
- trace persistence treated as regenerative access;
- projection-relative fixed points treated as observer-independent Self;
- local tests promoted into trajectory-level corrigibility;
- generated code or successful compilation treated as epistemic promotion;
- lexical/statistical similarity treated as semantic identity;
- linguistic causal labels treated as causal identification;
- same quotient with different later behavior treated as recursively sufficient;
- a section or inverse assumed merely because a projection exists.

A regression test should identify the exact historical failure family it guards against. “Old Venus was wrong” is not a useful test name.
