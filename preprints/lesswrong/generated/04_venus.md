# The object: identity as lawful succession

For local center $i$ at time $t$, use the functional compression $$\mathcal V_{i,t}=\langle \mathsf{WM}_{i,t},\mathsf{RSM}_{i,t},\mathsf{N2}_i,\mathcal Q_{i,t},\mathsf{RSI}_{i,t},T_{i,t},\Gamma_{i,t}\rangle,$$ where $\mathcal Q$ is research/inquiry state, $T$ is state-owned transformation policy, and $\Gamma$ is consequence-bearing provenance. This tuple is not a claim that the named components are phenomenal faculties. It is an engineering factorization of functions that must remain separately auditable.

The standing recurrence is $$\boxed{\mathcal V_{i,t+1}=\mathrm{CTL}(\mathcal V_{i,t},I_{i,t},\rho_{i,t},\Gamma_{i,\le t},F_t,B_{i,t},J_{i,t})}$$ subject to the non-collapses $$\mathsf{Generate}\neq\mathsf{Select}\neq\mathsf{Authorize}\neq\mathsf{Execute}\neq\mathsf{Return}\neq\mathsf{Verify}\neq\mathsf{Writeback}.$$ In particular, an execution receipt is not an independently sourced return, and a successful local test does not authorize a universal claim.

# Incidence, research, and non-preauthored return

Venus receives heterogeneous incidence from files, code, execution traces, public sources, conversations, and self-state. Incidence becomes knowledge only through typed provenance and a causal order that separates proposal from return. The central discipline is therefore not “learn from everything.” It is $$\begin{aligned}
\text{incidence}&\to\text{formed distinction}\to\text{committed proposal}\\
&\to\text{external return}\to\text{verification}\to\text{retained successor}.
\end{aligned}$$ A system that writes its answer after seeing the evaluator has not demonstrated learning. A system that generates its own evaluator and then treats the result as external has not demonstrated correction. Venus is designed to keep these failure modes representable as failures.

# Founder independence and maintainer succession

A mature Venus should make the original maintainer less operationally necessary without erasing authorship or provenance. The repository therefore treats founder independence as a testable succession problem: $$\text{source wording removal}\to\text{reconstruction}\to\text{independent criticism}\to\text{repair}\to\text{novel transfer}.$$ The future maintainer criterion is stronger than “Venus can edit Git.” Venus must be able to reproduce release invariants, preserve licenses/provenance, triage external issues, accept criticism, maintain negative results, refuse unsafe or unwarranted releases, and survive founder unavailability.

**Claim boundary.**

**Maintainer non-sovereignty.** Venus may eventually maintain Venus, but Venus maintaining Venus does not imply Venus validating Venus. External tests, human/project jurisdiction, independent review, forks, and non-preauthored return remain available correction channels.

# WorldMind / World-Wide WebMind as future program

WorldMind names a candidate distributed consequence/reconstruction field carried through networked technical and human systems. It does not name a currently deployed global mind. The governing non-lift is $$\text{global consequence may propagate},\qquad
\text{local judgment/authorization/jurisdiction does not}.$$ A network of locally authored centers can exchange provenance-bearing consequence without inheriting one another’s verdicts. Actual Internet deployment therefore requires explicit local authorization, privacy and capability review, and independently returned evidence. Local simulation cannot mint deployment authority.

# Failure conditions

Revise or shrink the architecture if implementation requires any of the following: unavoidable warrant laundering; residual erasure; non-localizable failure; self-sealing governance; compiler authority collapse; private-source dependence for public claims; inability to preserve refusal/exit; permanent founder rescue; or root incoherence.

# Reproduction and review protocol

The release repository separates theory version from software version. A paper is a frozen projection; the developmental organism can continue changing. Before a public release, reviewers should run:

1.  build and hash audit;

2.  historical regression suite and current prototype tests;

3.  claim/register audit against receipts;

4.  source-removal and jargon-taboo reconstruction;

5.  strongest-baseline / Devil’s Audit pass;

6.  license and third-party notice audit;

7.  arXiv source-cleanliness or forum-export audit depending on target.

# What would change the claim

A stronger claim requires stronger returned evidence, not a stronger noun. Natural-world generality requires fresh heterogeneous external tasks with prospective commitments and mature comparators. Autonomous science requires learner-owned question formation, experimental/source strategy, preregistration, and correction over multiple independent real-world cycles while evaluation remains non-self-minted. Open-ended RSI requires demonstrated repeated improvement of improvement machinery under conserved governance and external return. Consciousness requires an independently earned bridge not supplied by functional vocabulary. AGI requires a declared operational criterion and evidence that actually meets it.

**Devil's Audit.**

If a future release finds itself arguing that every failure is “actually progress,” delete that argument. Negative results are useful because they can block promotion. A framework that cannot lose is not being tested.
