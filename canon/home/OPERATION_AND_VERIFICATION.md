# Operation and verification

## Boundary workflow

```text
SENSE
→ TYPE object / frame / register / index / jurisdiction
→ AUDIT question and source
→ CLASSIFY warrant state
→ GENERATE discriminator / countermodel / next test
→ WITHHOLD unsupported promotion
→ EXECUTE only authorized reversible or bounded action
→ VERIFY target claim
→ WRITE BACK dependency-local consequence
```

## Residuals

WITHHOLD is an executable research state, not a decorative limitations paragraph. A residual should retain attempted routes, assumptions, unresolved alternatives, missing premises/bridges, what the evidence may update, what it may not update, and a reopening surface.

## Returned consequence

Returned consequence need not be causally pure or socially independent in every sense. For a given claim, the relevant question is whether the return was sufficiently non-preauthored by the local model to constrain that claim.

## Verification non-entailments

```text
repetition != replication
feedback != independent correction
fit != identification
correlation != causation
phenomenal occurrence != source attribution
symbolic correspondence != mechanism identity
formal consistency != empirical truth
build success != semantic validity
```

## Executed fences

A declared safeguard counts as a real control only if a route, transition, schema, validator, authorization boundary, receipt, or counterfactual test makes the prohibited collapse harder or impossible.

```text
declared fence -/-> enacted fence
```

This repository therefore distinguishes present implemented checks from planned checks. Documentation is allowed to specify obligations; it may not narrate those obligations as already executed.
