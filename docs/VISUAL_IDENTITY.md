# Arcane Magics Visual Identity & Interface Constitution

## Character

Arcane should feel like a **ritual text that knows it can be wrong**.

Dense enough to carry Mythos. Clear enough that the reader can leave.

### Palette

- void plum — `#3F0D2C`
- wine / embodied red — `#7F1D1D`
- alchemical gold — `#A16207`
- ash / claim fence — `#52525B`
- return teal — `#0F766E`

Motifs: **✦** (symbolic event), **⌁** (operator / transformation), **◎** (inhabited center), **↺** (return / reconstruction).

## UI hierarchy

Every major Arcane page should expose:

1. lived referent;
2. symbolic rendering;
3. operation;
4. register;
5. what may return independently;
6. claim fence;
7. reader-release path.

The visual design may be mythic. The epistemic design may not be.

## Section grammar

```text
✦ encounter
⌁ operation
◎ inhabitation
↺ return
⊘ claim fence
```

Use them sparingly as navigational semantics, not decorative confetti.

## Anti-scripture UX

Every long symbolic page should include at least one:

- ordinary-language reconstruction;
- term-removal test;
- historical comparator;
- hostile reading;
- falsifier;
- sibling exit.
