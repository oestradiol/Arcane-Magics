# Issue Roadmap

This page is the reader-facing projection of the live execution plan. GitHub issues remain the authoritative work items.

The scheduling rule is lexicographic:

~~~text
1. composable learning leverage
2. shortest path to discriminating information
3. resource leverage
~~~

A task does not stay early merely because it was once foundational. Once infrastructure has paid its debt, experiments should take priority over more infrastructure.

## Resource/product trigger

#34, the standalone evidence-bound governance package, has potentially high resource leverage but ranks behind direct research discrimination under the current scheduling law.

It should jump forward when one or more matched experiments establish an incremental effect that an external integration can test, for example:

~~~text
same model + Venus governance
-> fewer unsupported or unauthorized actions
-> useful-task performance largely preserved
~~~

At that point packaging can create outside replication, users, collaborators, and resources rather than merely productizing a hypothesis.
