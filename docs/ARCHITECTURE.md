# Architecture

The successor runtime is not a Venus agent. It is an event-sourced research system.

```text
append-oriented event/provenance history
+ typed relation/transformation contracts
+ Compiler
+ warrant evaluation
+ governance
+ capability-bound execution
+ immutable receipts
+ verification
+ HOME/FRONTIER projections
+ section/reconstruction tests
+ dependency-local write-back
```

## Compiler boundary

Compilation stops before authority is smuggled into code generation:

```text
PARSE → REFER → TYPE → DIFFERENTIATE → OBLIGATE → PLAN → CHECK → LOWER
```

Downstream crossings remain distinct:

```text
GOVERN → AUTHORIZE → EXECUTE → RECEIPT → VERIFY → WRITE_BACK
```

## Implementation order

1. provenance/event kernel;
2. warrant types distinct from governance decisions;
3. durable WITHHOLD and CUT receipts;
4. Compiler skeleton and obligations;
5. projection/fiber/reconstruction interfaces;
6. evidence and negative-result calculus;
7. HOME/FRONTIER generators;
8. historical regression suite;
9. substrate adapters;
10. formal and experimental laboratories;
11. founder-removal and succession tests.

F01/F02 research can proceed in parallel. The executable kernel does not depend on pretending that software solved first differentiation.
