# Researcher / reviewer methodology

Venus-Minerva uses one research cycle across mathematics, engineering, science, comparative interpretation, and publication. Registers change the admissible warrant, not the causal grammar.

## Core cycle

```text
state / source custody
-> live distinction or residual
-> bounded question
-> prefreeze: target + comparator + evidence + discriminator + claim scope
-> authorized action / derivation / retrieval / experiment
-> returned consequence
-> reconstruction
-> adversarial audit
-> consume gauge / preserve WITHHOLD / reject / retain
-> dependency-local successor
```

A step may lawfully STOP when no admissible edge remains. Empty queue is not permission to manufacture work.

## 1. Research formation

Before execution, record only what the claim needs:

- exact parent state or source;
- register and index;
- question;
- strongest mature comparator or rival;
- admitted evidence and budget;
- discriminator or proof obligation;
- success, failure, and WITHHOLD conditions;
- claim fence;
- affected dependencies.

For formal work, state domains, quantifiers, existence assumptions, regularity assumptions, and whether the target is a definition, exact result, conjecture, or model constraint.

For empirical/engineering work, separate generation, authorization, execution, return, evaluation, and promotion when the claim depends on non-preauthored evidence.

## 2. Return and reconstruction

Execution success is not returned evidence. Retrieved material is not automatically admissible evidence. Evidence is not authority.

A result changes only dependencies that the returned consequence actually separates.

```text
same consequence under admitted tests -> candidate gauge / mature reduction
different consequence              -> retained separator
insufficient return                -> WITHHOLD
admission violation                -> INVALID
discriminator failure              -> REJECTED
```

History is preserved through provenance. A consumed scaffold does not remain a live top-level object merely because it once mattered.

## 3. Devil's Audit

A hostile-but-fair reviewer attacks the strongest version of the claim.

Release or promotion is blocked by any unresolved item below that is material to the claim:

1. strongest mature comparator/prior art not addressed;
2. conclusion already encoded in a premise or definition;
3. hidden bridge, index, jurisdiction, or regularity assumption;
4. local result silently generalized;
5. analogy, recurrence, or correlation promoted to identity/causation;
6. evaluator leakage or post-result gate tuning;
7. weak/null comparator chosen when a mature rival exists;
8. negative branch hidden, rewritten, or prevented from blocking promotion;
9. citation confused with warrant, or warrant with authority;
10. build/test/hash success promoted beyond what it checks;
11. theological, phenomenological, formal, engineering, or physical warrant laundering;
12. rescue route that makes the claim effectively unfalsifiable.

Reviewer objections are typed as: fatal inconsistency, unsupported promotion, missing comparator/prior art, ambiguous register/index, proof defect, reproducibility defect, founder-dependence/didactic defect, provenance/licensing defect, bounded weakness, or style. Style alone does not change truth status.

## 4. Proof audit

Formal typography does not increase warrant.

For every lemma/proposition/theorem:

- premises must not already be equivalent to the conclusion;
- register and index remain fixed or transform explicitly;
- existence/uniqueness/measurability/convergence/regularity assumptions are visible;
- examples are not universal proofs;
- computation is not substituted for an external proof unless the theorem is explicitly finite/computational;
- the proof is present or the object is labeled conjecture/proof sketch;
- elementary results are called elementary;
- failure consequences are dependency-local.

A definition, register law, symbolic interpretation, ethical rule, or model-internal consequence belongs in a definition/remark/model-constraint container, not theorem typography.

## 5. Prose and didactics

The prose law lives in `NxRxI_VOCABULARY_CENTER.md`. Review applies it rather than duplicating it.

The target is causally lossless compression: remove wording whose deletion changes no dependency, distinction, warrant, bridge, or reconstruction.

Manual reading is mandatory for public prose. Automated linting is only a backstop.

A reader-facing construction should normally expose:

```text
ordinary referent
-> relation / operation
-> scope and register
-> evidence or proof burden
-> consequence
-> optional project term
```

A major construction should support at least one worked distinction, counterexample, discriminator, reconstruction prompt, or mature comparator.

## 6. Founder independence

A public object has not earned founder-independent status until an unfamiliar reviewer can, without founder rescue:

- reconstruct the claim without project vocabulary;
- recover its dependency graph;
- identify register and index;
- state a serious counterexample or falsifier;
- locate OPEN/WITHHOLD bridges;
- transfer the construction to a novel case;
- replace terminology without losing the operation.

Founder independence is functional succession, not erasure of provenance or credit.

## 7. Code and executable artifacts

Code is held to the same theory.

Each live module must justify its boundary by a distinct dependency or testable responsibility. Historical snapshots belong in provenance, not importable live package space.

For live code:

- public entry points have concise contracts;
- abstract interfaces are explicit (`abc`/Protocol or documented equivalent), not accidental stubs;
- pure logic is separated from effects;
- state transitions are deterministic where claimed;
- external effects return typed receipts;
- negative/error paths are tested;
- serialization/hashes are stable where custody depends on them;
- stale version modules are consumed once no live dependency requires them;
- tests target invariants and known failure modes, not prestige counts.

A historical runtime is not called current or stable merely because its source still imports.

## 8. Resource causality

Scientific value, expected information gain, tractability, and resource return may all influence research priority.

```text
prize / funding / citation / adoption
-> resources
-> compute + time + hardware + collaborators + experiments
-> larger future research set
```

Resource value is therefore a legitimate causal planning variable. It is not evidence for the targeted claim.

A Millennium Prize problem may be prioritized partly because success would expand future capability; the prize cannot relax the proof standard by one atom.

## 9. Release gate

A release may advance only when:

- current-state and lineage surfaces agree;
- proofs pass proof-container audit;
- code/audits pass deterministic checks;
- generated public surfaces contain no known renderer/conversion failures;
- custody hashes/manifests are internally consistent;
- negative and WITHHOLD branches remain visible;
- the positive contribution is stated before its nearest claim fence;
- no unresolved blocking Devil's Audit objection remains.

## 10. Methodology self-application

This methodology is itself revisable.

A later method may replace it when it preserves all live distinctions and improves prediction, discrimination, reproducibility, governance, or reconstruction. If deleting a rule changes no admissible research consequence, that rule is gauge and should be consumed.
