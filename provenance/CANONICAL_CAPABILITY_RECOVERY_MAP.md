## Rule

Do not reimplement an earned capability until its Canonical realization has been classified as non-transplantable into the current Git carrier.

The relevant distinction is:

```text
same kernel code
!= same VM state
!= same TransformProgram
!= same research state
!= same return path
!= same executable developmental organism
```

A historical harness result is donor evidence. A restart-persistent state object is stronger. A current Git descendant is stronger still only when the old causal function is actually executable.

## Why the skill appeared to disappear

The old capability equation was effectively:

```text

+ journal/state root
+ TransformProgram
+ RSM/research state
+ active improver
+ World-return interface
+ evaluator/governance
= executable capability
```

Git retained much of the kernel and a great deal of provenance, but did not boot the exact U1/U2 state objects. Some descendants were reimplemented around EDU16 and the GitHub worker. Therefore skills can be absent from the present routing even though their historical code substrate or theory remains.
