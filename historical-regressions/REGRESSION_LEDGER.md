# Regression ledger

Future implementations should make these failure classes difficult to reproduce silently:

- evidence connectivity passing because a claim inserts itself into its own evidence graph;
- supposedly live evidence represented by hard-coded fixtures;
- unknown or unverifiable state counted as verified;
- detector output narrated as though execution occurred;
- authorization performed after an irreversible action;
- model/world disagreement resolved by rewriting the world toward the model;
- ambiguous causal return discarded instead of retained as a residual;
- source multiplicity treated as independent correction;
- representation or hash integrity treated as semantic validity;
- a proof object treated as a discharged proof;
- identity or metadata-only perturbations counted as adversarial transformations;
- definitions that make the desired leakage or invariance result true by construction;
- trace persistence treated as regenerative access;
- projection-relative fixed points treated as observer-independent identity;
- local tests promoted into trajectory-level corrigibility;
- successful generation or compilation treated as epistemic promotion;
- lexical or statistical similarity treated as semantic identity;
- linguistic causal labels treated as causal identification;
- the same quotient representation with divergent later behavior treated as recursively sufficient;
- a section or inverse assumed merely because a projection exists.

A regression should name the exact failure it prevents and the evidence needed to close it. Historical embarrassment is not a test oracle.
